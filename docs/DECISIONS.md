### D-001 — Keep the pharmacy domain; do not re-theme
**Phase:** 0
**Decision:** Retain the pharmacy/healthcare-supply-chain domain, re-frame the
project from "a pharmacy database" to "a replenishment decision system."
**Why:** The re-theme bar was *materially stronger AND schema-reusable*. The existing
schema already contains every entity the flagship problem needs, and the problem is
demonstrably funded at Amazon SCOT, CVS, Walgreens and large chains. A re-theme costs
~1 week and buys nothing.
**Alternatives rejected:** e-commerce demand forecasting (schema reuse is
superficial, domain is saturated in portfolios); fintech fraud detection (would
discard the entire existing schema).

### D-002 — PostgreSQL as the OLTP target, not Oracle
**Phase:** 2
**Decision:** Port the Oracle PL/SQL schema to PostgreSQL 16.
**Why:** Oracle SQL Developer on Windows is a hard barrier to anyone evaluating the
repo. Reviewer reach is the point of a portfolio project. Postgres also runs free in
CI and in every cloud free tier.
**Cost accepted:** Oracle-specific PL/SQL (`DBMS_OUTPUT`, `VARCHAR2`, `EXECUTE
IMMEDIATE` drop blocks) must be rewritten as PL/pgSQL. The original Oracle scripts are
preserved unmodified under `legacy/` for provenance.

### D-003 — Synthetic data, generated by a simulator, not scraped or real
**Phase:** 3
**Decision:** All transaction data is generated by a seeded simulator.
**Why:** Three reasons, in order of importance. (1) Real prescription data is PHI and
cannot be committed to a public repo. (2) A simulator gives **known ground truth** for
injected anomalies, which is what makes honest precision@k measurement possible at
all. (3) It allows controlled stress tests — supply shocks, demand regime changes —
that no static public dataset offers.
**Limitation accepted and to be stated in the README:** results demonstrate method
correctness on data whose generating process we control. They are not evidence of
real-world clinical or commercial performance. Public reference vocabularies
(RxNorm/openFDA) anchor SKU metadata to reality where possible.

### D-004 — Total cost in ₹ is the primary metric, not WAPE
**Phase:** 0/6
**Decision:** Headline results are reported as total cost (stockout penalty +
holding + waste). Accuracy metrics are diagnostics only.
**Why:** A forecast improvement that does not change the order quantity has no value.
Reporting only WAPE is the most common way portfolio forecasting projects avoid
demonstrating impact.
