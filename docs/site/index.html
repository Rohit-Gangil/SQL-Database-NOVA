Two results that went against me

The censoring correction made WAPE worse

Training on the censoring-corrected target scores 0.8928 against 0.8854 for raw sales — worse. But bias falls from -0.062 to -0.015. I expected the correction to improve both. It did not.

WAPE is symmetric; the inventory decision is not. A forecast that is systematically low under-orders, causes a stockout, observes the censored sale and forecasts lower again. That loop is invisible to WAPE and fatal in production, so the corrected target ships.

The trailing 28-day mean beat Croston and SBA

On series this lumpy, Croston’s separate size/interval smoothing buys nothing over a plain mean. TSB comes closest of the three, as expected, because it decays for discontinued items.

The decision layer

Order quantities come from the newsvendor critical ratio, computed per SKU: CR = Cu / (Cu + Co), where underage is the unit margin scaled by criticality (1.0× for a convenience item, 12.0× for a life-critical drug) and overage is holding cost plus expiry risk. This is the substantive claim: one chain-wide safety factor cannot be right for both a cardiac drug and a vitamin.

The fix that made this possible

The project began as an Oracle DBMS coursework assignment. Its inventory table:

CREATE TABLE Stock (
    pharmacy_1 VARCHAR2(100) PRIMARY KEY,  -- one row per pharmacy, ever
    stock      VARCHAR2(100)               -- inventory as a *string*
);

No drug column, no date column, no numeric quantity. It could not answer “how many units of drug D does branch B hold on date T” — the only question this project depends on. It is now an inventory ledger with per-lot expiry tracking and a CHECK-enforced flow identity, verified on all 5,918,400 rows.

What this is not

The data is synthetic. All of it. No real patient data has ever been loaded. That is deliberate — it is what makes measurement against known ground truth possible — and it is the single biggest limitation: these results show the methods work on data whose generating process I control.

The PostgreSQL layer is UNVERIFIED. The build machine had no Docker and no psql, so db/*.sql has never been executed. No EXPLAIN ANALYZE numbers are claimed anywhere.

Not built: hierarchical reconciliation (MinT/OLS), deep sequence models (TFT/N-BEATS), GNN anomaly detection, causal uplift, FastAPI/ONNX serving, drift monitoring, and the text-to-SQL eval harness. Ground truth for the anomaly, drift and causal work is generated and waiting.
